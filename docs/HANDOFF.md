## Что сделано (этап 0 — MVP)

1. Ядро: TinyCore (мини-трансформер), CharTokenizer, CoreConfig.
2. Механизм модулей: LoRA (inject/remove/detach, save/load npz).
3. ModuleHub: скан каталога, валидация манифестов, connect/disconnect,
   конфликт целей, describe() = «что ИИ знает прямо сейчас».
4. Демо-модуль `demo_math`: таблица сложения 0..4, точность 1.0 (25 фактов),
   loss 2.74→0.44 за 400 шагов CPU, веса `modules/demo_math/weights/lora.npz`.
5. 31 мини-тест, все зелёные (~7 сек), включая e2e «знает ровно то,
   что подключено».
6. Документация: README, ARCHITECTURE, MODULE_FORMAT, MODULE_GUIDE,
   COLAB_TRAINING, этот HANDOFF.

## Факты, без которых понимание ломается

1. **Веса модуля привязаны к ядру бит-в-бит**: demo_math обучен под ядро
   `seed=0, d_model=64, n_layers=2, vocab=14` (см. train.py). E2E-тест
   воспроизводит ядро именно с seed=0. Другой seed = мусор на выходе.
2. Ядро всегда заморожено: `requires_grad` только у `lora_*` (инвариант
   проверяется тестом).
3. Необученный модуль (B=0 или без файла весов) при подключении ничего
   не меняет — проверено тестом.
4. Один модуль на слой: пересечение `targets` → `ModuleConflictError`.
5. Отключение модуля возвращает логиты ядра бит-в-бит (проверено e2e).
6. Правила работы: тесты ПЕРЕД кодом; логирование везде; маленькие файлы;
   документация обновляется каждый сеанс.
